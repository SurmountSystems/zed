# Zed + Grok Build Integration — Living Plan

**Primary Goal (updated 2026-05-20 — Full Native Replacement Commitment):**  

Zed must deliver a **complete, fully independent native Rust + GPUI re-implementation** of Grok Build that replicates **all** of its capabilities inside the editor, with no runtime dependency on the external `grok` binary for core functionality.

This means:
- 1.2: A complete Full Native Grok Build, fully rewritten in Rust, fully compatible with Grok Build's sqlite formats, delivered through native GPUI visuals in Zed.
- 1.3: All Grok Build functionality implemented, with **every bridge** to the external grok binary replaced by full Rust implementations, plus full test coverage. This explicitly includes:
  - A non-bridged, fully independent, cross-compatible implementation of Grok Build (full sub-agent tracking with personas and capability modes, rich non-TUI GPUI visuals, all skills/personas, monitor background tasks, plan approval flows, etc.).
  - Modifications to Zed's agent/ACP layer so that **IDE-based diagnostics** (errors and warnings from rust-analyzer and other language servers) become the primary, always-available, non-blocking, cross-language context for the agent. The agent must be instructed to rely on Zed-sourced lints first instead of forcing or preferring local `cargo` / shell builds.
  - Zed provides real system (desktop + in-Zed) notifications when all autonomous work finishes (the exact completion notification required by the behavioral rules).

The external `grok` binary and its ACP interface are now considered **legacy compatibility only**. They may be used optionally by users who still run the standalone TUI, but they are no longer the source of truth or a required path for new Grok Build work in Zed.

**Guiding Constraints (non-negotiable):**
- Full native replacement is the only primary goal. Incremental bridging is explicitly rejected.
- Linux-first, then Mac/Windows.
- Native Rust + GPUI only. Efficiency and latency are first-class requirements.
- TDD with production-quality test coverage for the entire native implementation.
- All changes follow CLAUDE.md (existing files, full words, proper error handling, no creative low-level additions).
- 16-agent parallel execution wherever possible, with ruthlessly native charters.

### ZT-1 Reusable Component Usage (Bridged Path Priority — for the Broader Zed Team)

The ZT-1 (ZedTodos) surface is now a first-class reusable native GPUI component. Docks, panels, global surfaces, and custom views throughout Zed can own `ZedTodosComponent`, drive it against any bridged Grok `AcpThread` (ACP external or native is_grok_build_profile), collect categorized items, classify with unified RO/Destructive rules, toggle expansion for efficiency, render the exact rows and chips, and wire the same actions — all without duplicating logic or private state from ThreadView.

**Concrete consumption patterns (copy-paste ready — see also the authoritative high-quality examples in docs/src/ai/external-agents.md under "Reusing the ZT-1 ZedTodosComponent")**

**State ownership** — every dock/panel owns its own instance:

```rust
use agent_ui::{ZedTodos, ZedTodosComponent, ZedTodosDockPrototype};
pub struct MyDock { pub zed_todos: ZedTodosComponent, thread: WeakEntity<AcpThread>, ... }
impl MyDock { fn new(t: WeakEntity<AcpThread>, cx: &mut App) -> Self { Self { zed_todos: ZedTodosComponent::new(), thread: t, ... } } }
```

**Collectors + counts** (always go through the component):

`ZedTodosComponent::collect_pending_approval_tool_calls(thread)`, `collect_background_monitor_tool_calls`, `pending_approval_counts(thread)` (returns (total, ro, destructive)).

**Toggles** (five methods, all mutate `self.zed_todos.state`):

`toggle_approvals_expanded()`, `toggle_plan_expanded()`, `toggle_background_tasks_expanded()`, `toggle_grok_memory_expanded()`, `toggle_background_monitor(id)` + `is_background_monitor_expanded(&id)` and direct state bool reads. Call `cx.notify()` after.

**Row helpers** (re-exported at agent_ui root): `render_risk_chip`, `render_approval_row` (takes the four pre-built action AnyElements), `ZedTodosComponent::render_plan_entry_row`, `render_background_task_row`, plus the one-call `render_zed_todos_categorized_surface(approvals, plan, monitors, memory, &state, window, cx)` for quick assembled gated surface.

**Action wiring** (the six builders on ZedTodosComponent — supply your listener or weak-move closure):

`build_allow_once_action(idx, risk, on_click)`, `build_allow_always_action`, `build_granular_allow_action`, `build_deny_action(idx, risk, is_always, on_click)`, `build_plan_accept_button(risk, on_click)` + the option extractor `pending_approval_options_for_tool_call` and label/color formatters. Risk flows through for correct "(RO)" / "(Destructive)" text and icon/color.

**Real dock today**: `ZedTodosDockPrototype::new(weak_thread, cx)` is a fully functional, self-contained, classified ZT-1 dock (owns component, wires actions with weak dispatch, renders using exactly the public surface). Use it directly or copy its render body.

All paths (external ACP + native `is_grok_build_profile`) are identical. Efficiency: collapsed paths are O(1) by design; collectors are post-idle filters; heavy content is lazy-gated.

The external-agents.md consumer guide now contains the full copy-paste-ready dock skeleton, exact method signatures, and wiring patterns. This turns the extracted component into a first-class primitive any Zed crate can consume without private knowledge or duplication.
